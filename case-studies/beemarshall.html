BeeMarshall — Hive Management for a Golden Bay Apiarist

Paper notes and memory do not scale when hives are scattered across rural sites. We built a mobile staff app so the operator can find clusters, schedule work, and navigate between yards. Try the simulated field run and roster below — they model the same pattern.

Problem

Field work without a field system

A local apiarist needed one place for hive locations, reminders, who is assigned to which yard, and how to get there — not another generic project board that ignores GPS and seasonal bee work.

What we built

Owned ops software, not a subscription stack

  • GPS hive clusters mapped for navigation between sites
  • Reminders and scheduling sized to seasonal hive work
  • Task allocation across yards and staff
  • Mobile-friendly staff workflow handed over in accounts the client controls

Try the sim: Hive Run (field staff) · Apiary Board (management). Live staff app: BeeMarshall on GitHub Pages

Outcome

Why this is citeable

This is not a template “beekeeping website.” It is a first-party operational system for a named local industry pattern — GPS clusters, yard navigation, and hive-task scheduling — built once and owned by the operator.
